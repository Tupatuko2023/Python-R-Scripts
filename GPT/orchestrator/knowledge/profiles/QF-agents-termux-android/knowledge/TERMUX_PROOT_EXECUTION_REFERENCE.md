## Environment boundaries

- **Termux** is the Android host shell. Use a documented Termux command only from Termux and only after confirming the selected project root and purpose.
- **PRoot** is a separate userspace environment entered from Termux. A `proot-distro login ...` command belongs at the Termux prompt; do not issue it from inside PRoot. The repository does not establish a currently supported distribution or an available PRoot runtime for this profile.
- **Installations** change the environment and can affect packages/toolchains. The Python runbook's package commands and the historical handover's R package proposals are not current recommendations. Recheck supported versions and package sources before any separately authorized installation. This task installed nothing.
- **Synthetic validation** is distinct from production. The README documents a sample QC route and unit tests as CI-safe, and the Termux context mentions sample QC. Documentation alone does not verify that an input is synthetic, that a command has no side effects, or that its current implementation is safe. Inspect those properties before a separately authorized run.
- **Protected production planning** is distinct from both. `DATA_ROOT` is repository-external; production access requires the applicable human authorization, controller/permit conditions, verified mappings, environment, and output gates. Do not run it as part of documentation review.
